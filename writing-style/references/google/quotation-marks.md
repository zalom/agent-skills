# Quotation Marks
Source: https://developers.google.com/style/quotation-marks

Use straight double quotation marks and apostrophes (never curly/smart quotes) — for consistency and easier writing/reviewing.

## When to use quotation marks
Titles of shorter works (articles, episodes) unless part of a link — use italics for full-length works instead.

| Guidance | Example |
|---|---|
| Referring to a section of a larger document/video that can't be linked directly | "The technique is described in the section 'Deploying containers' of the Containers overview video." |
| Referring to a parent document's title when already linking to a section | "The machine learning (ML) workflow section of 'Introduction to Vertex AI' describes..." |
| Directly citing a person or quoting a slogan/motto | "Martin Fowler has said, 'We are still learning the techniques to write software effectively.'" |
| Using a term metaphorically, if not established usage in the domain | "This configuration forms an 'island' within the network that is not connected to the external network." |

## Punctuation placement
Commas and periods go inside quotation marks — EXCEPT when quoting a keyword or other literal string, where punctuation goes outside (quotation marks there indicate an exact literal string; don't add anything extraneous inside). Generally, don't put quotation marks around code-font items unless the marks are literally part of the item. If the quoted material ends with a question mark or exclamation point, don't add a period.

## Single quotation marks
Only two uses: in code examples for languages using single quotes; and when nesting a quotation inside another quotation (primary quote in double marks, nested quote in single marks).
