# Possessives

Source: https://developers.google.com/style/possessives

## General rules
- Singular nouns (including those ending in *s*): add *'s*.
  - Recommended: "Modify each vector's record." / "Raise the storage class's quota."
- Plural nouns ending in *s*: add only an apostrophe.
  - Recommended: "Extend the models' capabilities." — Not recommended: "Extend the models's capabilities."
- Plural nouns not ending in *s*: add *'s*.
- If a possessive seems awkward, rewrite to omit it.
  - Recommended: "Analyze the business data." — Not recommended: "Analyze the businesses' data."
  - Recommended: "The rule that the Federal Trade Commission (FTC) issued." — Not recommended: "The Federal Trade Commission's (FTC's) rule."
- Never use *'s* to form a plural (see Pluralization).

## Product, feature, and company names
- Never form a possessive from a feature/product name or trademark when describing function/performance — use it as a modifier or rephrase with "of."
  - Recommended: "You can use this template to monitor Google Search performance." / "...to monitor the performance of Google Search."
  - Not recommended: "You can use this template to monitor Google Search's performance."
- Company names: add *'s* for possession, EXCEPT when the name is being used as a trademark.
  - Recommended: "Google's new office is nearby." — Not recommended: "The capabilities of Google's Search are vast."
  - See Trademarks for using trademarks as adjectives, not nouns.

## Code items
Never form a possessive of a code item — form the possessive from the following noun, or rewrite to avoid it.
- Recommended: "Compare the number to the `wordCount` method's return value." / "Compare the number to the value returned by the `wordCount` method."
- Not recommended: "Compare the number to `wordCount`'s return value."
- See Grammatical treatment of code elements.
