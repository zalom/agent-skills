# Periods and Other End Punctuation
Source: https://developers.google.com/style/periods

## Basic rule
End complete sentences with a period, except in lists or headings (unless a question).

## URLs
Avoid ending a sentence with a URL immediately followed by a period (confusable with the URL itself). Fixes: avoid URLs in running text; rewrite so the URL isn't sentence-final; put the URL on its own line, omitting the final period. If you must put a period right after a URL, leave no space between them. Link-styled text (e.g., blue) helps visually separate the period from the URL.

## Quotations
Place the period inside quotation marks, even if not part of the quoted material — EXCEPT when quotation marks indicate an exact literal string (e.g., a keyword), in which case the period goes outside. If the quoted material ends with a question mark or exclamation point, don't add a period.

## Parentheses
If the parenthetical is a complete sentence, put the period inside; if part of a larger sentence, put the period after the closing parenthesis.

## Headings
Never end a heading with a period.

## Decimals
Use a period for the decimal point (not a comma, which is customary in some non-US countries).

## Abbreviations
Period after a shortened word; never after the letters of an acronym/initialism.

## Spacing
Only one space between sentences.

## Exclamation points
Generally avoid exclamation points — unprofessional, alarming, or poorly translated.
- **Concept/reference docs**: never use exclamation points; maintain a neutral, objective tone.
- **Procedural topics**: avoid; use a period for completion steps ("The VM is created.").
- **Blog posts**: OK to convey enthusiasm, but not in every paragraph.
- **Code examples**: OK when required by syntax (e.g., `!=`).
- **System literals**: OK when part of an exact error code/log message that must be matched.
- **Tutorials/learning modules**: use sparingly for milestones ("Congratulations! You've completed the setup.").
